# 1. 용어 정의 (Glossary)

`docs/glossary.md`

가격/기술적 분석 에이전트에서 쓰는 용어를 한 곳에 정의한다. 모든 문서·코드·프론트가 이 정의를 따른다.

## 핵심 산출물 용어

| 용어 | 정의 | 값 | 누가 정하나 |
| --- | --- | --- | --- |
| **daily_regime** | 일봉 지표만으로 판정한 1차 국면 (보정 전) | 6종 + 판단불가 | 코드 (규칙) |
| **final_regime** | 최종 국면 라벨. daily_regime과 같은 6종 체계 유지 (라벨을 늘리지 않음) | 6종 + 판단불가 | 코드 (규칙) |
| **weekly_trend / monthly_trend** | 주봉·월봉의 추세 방향 | 상승/하락/횡보/판단불가 | 코드 |
| **alignment_flag** | 일봉 국면과 상위 추세의 정합 여부 | 정합/역행/중립 | 코드 |
| **regime_context** | 멀티프레임 보정을 설명하는 문구 (라벨이 아니라 설명) | 텍스트 | 코드/템플릿 |
| **signal_score** | 5개 지표 신호를 가중 집계한 점수. **방향·세기** | -1.0 ~ +1.0 | 코드 (가중집계) |
| **consensus** | signal_score를 임계값 규칙으로 라벨링한 최종 신호 | 5종 (아래) | 코드 (임계값) |
| **confidence** | 그 판단을 얼마나 믿을 만한가. **신뢰도**. signal_score와 별개 축 | 0.0 ~ 1.0 | 코드 (계산식) |
| **confidence_basis** | confidence 근거 문장 | 텍스트 | 코드 |
| **risk_flags** | 코드가 생성하는 구조화된 리스크 라벨 배열 | 배열 (enum) | 코드 |
| **risk_notes** | risk_flags를 기반으로 생성한 사실 서술형 문장 | 배열 | 코드/템플릿 |
| **technical_signals** | 지표별 기술 신호 배열 (지표마다 판정·수치·설명) | 배열 | 코드 + LLM (아래 분리) |
| **signal** (개별) | 각 지표의 긍정/중립/부정 판정 | positive/neutral/negative | 코드 |
| **detail** | 그 지표의 확정 signal·수치를 자연어로 푼 설명 문장 | 텍스트 | LLM (서술만, 판정 불변) |
| **interpretation** | 확정된 라벨·수치를 자연어로 푼 종합 해석 문장 | 텍스트 | LLM (해석만) |

## consensus 5종 (라벨 확정)

투자 권유로 읽히는 "매수/매도" 대신 사실 서술 톤을 쓴다.

| 코드값 | 표시 라벨 | signal_score 범위 |
| --- | --- | --- |
| `strong_positive` | 긍정 우세 | score ≥ 0.5 |
| `weak_positive` | 약한 긍정 | 0.3 ≤ score < 0.5 |
| `neutral` | 중립 | -0.3 < score < 0.3 |
| `weak_negative` | 약한 부정 | -0.5 < score ≤ -0.3 |
| `strong_negative` | 부정 우세 | score ≤ -0.5 |

*경계값은 포함(≥, ≤). 매수·매도 동시 존재 + |score| < 0.3이면 "중립(신호 엇갈림)"으로 표기.*

## signal_score vs confidence — 자주 헷갈리는 구분

두 개는 **완전히 다른 축**이다.

- **signal_score** = "긍정이냐 부정이냐, 얼마나 강하냐" (방향·세기). 예: +0.30 = 약한 긍정
- **confidence** = "그 판단을 믿을 만하냐" (신뢰도). 예: 0.42 = 보통

독립적으로 조합된다. "약한 긍정인데 신뢰도는 낮음"(방향은 긍정 쪽이나 신호가 충돌해 확신 못 함)이 가능하다.

## final_regime vs consensus — 자주 헷갈리는 구분

- **final_regime** = 차트의 **상태** (상승 전환 관찰, 과열, 횡보…). 지표 배열·RSI에서 나옴
- **consensus** = 5개 지표의 **신호 종합** (긍정 우세/중립/부정 우세…). signal_score에서 나옴

같은 종목이 "regime=과열"이면서 "consensus=약한 긍정"일 수 있다. 국면(상태)과 신호(방향)는 다른 것을 측정한다.

## detail vs interpretation — LLM이 푸는 두 문장

LLM(노드 10)이 생성하는 자연어 문장은 두 종류다. 둘 다 코드가 확정한 값을 서술만 하며, 판정·수치를 만들지 않는다.

- **detail** = 지표 **하나**의 확정값(signal·수치)을 푼 짧은 설명. `technical_signals[].detail`. 예: "20일선이 60일선을 상향 돌파해 골든크로스가 관찰됩니다."
- **interpretation** = 여러 지표·국면을 **엮은** 종합 해석. 리포트 상단 요약 문단.

둘은 노드 10에서 **한 번의 LLM 호출**로 함께 생성되고, 둘 다 검증 ③(라벨 왜곡)의 대상이다. 실패 시 각각 템플릿 폴백으로 떨어지며 출처(`detail_source`·`interpretation_source`)에 기록된다.

**코드/LLM 경계:** `technical_signals[]` 안에서도 판정(`signal`)·수치(`value`·`metrics`)·가중치(`weight`)는 **코드**, 설명(`detail`)만 **LLM**이다. 한 항목 안에 두 출처가 공존한다. 이 경계가 veriθ 신뢰성 설계의 축이며 화면에서도 색으로 구분된다(코드=청록, LLM=보라).

## 멀티프레임 — 라벨을 늘리지 않는다

최종 regime은 일봉 6종 체계를 그대로 유지한다. 상위 타임프레임(주/월봉)은 **라벨을 바꾸지 않고** `alignment_flag`와 `regime_context`로만 반영한다. "상승 중 단기 과열" 같은 조합 라벨을 만들지 않는다 — 라벨이 폭발하면 검증 ②가 불가능해지기 때문이다.

예1 (방향성 있는 국면 — 정합/역행 판정): 일봉 상승 전환 관찰 + 월봉 하락 → `final_regime="상승 전환 관찰"`, `alignment_flag="역행"`, `regime_context="월봉 추세는 하락으로, 일봉의 긍정 신호는 대세 하락 안의 단기 반등일 수 있습니다."`

예2 (중립 국면 — 정합/역행 판정 안 함): 일봉 과열 + 월봉 상승 → `final_regime="과열"`, `alignment_flag="중립"`, `regime_context="상위 추세는 상승이나 일봉 기준 단기 과열이 관찰됩니다."`

*과열·과매도·횡보는 성격이 중립이라 방향성 판정(정합/역행)을 하지 않고 `alignment_flag="중립"`으로 두되, 상위 추세 맥락은 `regime_context`에 설명한다. 정합/역행은 방향성 있는 국면(상승 전환 관찰·상승 추세 유지·하락 추세)에만 적용한다.*

## 상태 용어

| 코드값 | 표시 | 언제 뜨나 |
| --- | --- | --- |
| `normal` | 정상 | 데이터 정상 확보 |
| `stale_cache` | 최신 시세 미반영 | KIS 실패 + stale 캐시 폴백. 일부 또는 전체 타임프레임이 최신봉까지 반영되지 않음 |
| `data_limited` | 데이터 제한 | KIS 실패 + 캐시도 없음, 또는 주봉/월봉 등 상위 타임프레임 일부 미확보 |
| `regime_unavailable` | 판단 불가 | 봉 수 부족으로 국면 판정 불가 (종합·신뢰도 스킵) |

## 검증 용어

| 용어 | 정의 |
| --- | --- |
| **검증 ① 계산 정확성** | 지표 계산이 라이브러리와 일치하는지 mock 테스트 |
| **검증 ② regime 규칙** | 입력 지표가 정확한 regime 라벨로 나오는지 (보정 포함) 테스트 |
| **검증 ③ LLM 라벨 왜곡** | 코드 확정 라벨과 LLM 출력 라벨이 일치하는지 trajectory eval |
| **재생성** | 검증 ③ 실패 시 라벨을 강제 주입해 LLM 해석을 1회 다시 생성 |
| **템플릿 폴백** | 재생성 후에도 실패 시 LLM 문장을 버리고 코드가 채운 문장으로 대체 |
| **trace** | 전 구간의 입력·계산·라벨·신호 기록. 역추적용 |

## 구조 용어

| 용어 | 정의 |
| --- | --- |
| **Top Supervisor** | 팀 공용 상위. 쿼리 변형·병렬 디스패치만. 종합·판단 안 함 |
| **Technical Supervisor** | 가격/기술적 분석 에이전트 내부 조율자. 모듈 결과를 종합해 기술적 국면·신호·리스크를 산출한다. **전체 투자 판단은 하지 않는다** (기술적 분석 내부의 종합일 뿐) |
| **Module** | 에이전트 내부 기능 단위 (Sub-Agent 아님). LLM 호출 최소 |
| **Node** | LangGraph 흐름의 각 단계. 얇은 어댑터 (로직은 옆 모듈에) |
