# 이벤트 병합 로직 (event_merge)

> 여러 기사를 하나의 이벤트로 묶는 로직. news 에이전트에서 가장 까다로운 부분.

## 1. 문제

LLM이 기사를 각각 읽으면 같은 사건을 제각각 다른 이름으로 뽑는다.
- 기사1: "AI 투자 확대"  기사2: "미국 공장 투자"  기사3: "AI 투자 규모 공개"
- 사실 같은 사건 → 하나로 합쳐야 함.

## 2. 왜 이벤트명이 아니라 summary로 병합하나

이벤트명은 짧아서 반대 의미도 겹친다.
- "AI 투자 확대" vs "AI 투자 축소" → '투자' 때문에 임베딩이 가까워짐(오병합 위험).

→ LLM이 만든 **summary**(맥락 담긴 문장)를 임베딩한다.
- "삼성전자가 미국 공장에 AI 반도체 생산시설을 확대하기로 결정" → 훨씬 안정적으로 묶임.
- 임베딩 모델은 **arctic-embed-l-v2.0-ko**(services/embedder.py). 기사끼리 유사도 비교(대칭)라
  검색용 query/document 프리픽스 없이 모든 summary를 같은 방식으로 임베딩한다.

## 3. 가중 점수 (summary만으로는 부족)

summary만 보면 "삼성전자 AI 투자"와 "SK하이닉스 AI 투자"가 회사가 다른데 합쳐진다.
세 신호를 가중 결합:

```
score = 0.6 · summary_similarity
      + 0.3 · company_overlap
      + 0.1 · time_proximity
```

- **company_overlap**: 회사가 다르면 0 → 다른 회사 사건 병합 방지.
- **time_proximity**: 시점이 멀면 낮음 → 3개월 전 "투자 확대"와 오늘 것을 구분.
- 계수(0.6/0.3/0.1)는 임시값. 실데이터로 튜닝. config.py에서 읽는다.

## 4. 병합 판정 (억지 편입 방지)

```
새 기사 → 후보 이벤트들과 score 계산
  → 제일 높은 score가 임계값 이상? 
      예 → 그 이벤트에 편입
      아니오 → 새 이벤트 생성
```

- "제일 가까운 것"을 무조건 받지 않는다. 임계값 미만이면 거부하고 새 이벤트.
- 임계값도 실데이터 튜닝값. config.py.

## 5. 후보 축소 (성능)

새 기사를 **모든** 이벤트와 비교하면 이벤트가 수만 개일 때 느리다.
후보를 먼저 줄인다:
- **같은 회사 이벤트** + **최근 7일 이벤트**만 비교.
- 7일 롤링 삭제 때문에 살아있는 이벤트가 7일치라 큰 문제는 자동 완화.
- 확장 시 pgvector ANN으로 근접 후보만 조회.

## 6. canonical (이름 고정)

새 기사가 "HBM3E 공급 확대", "HBM 양산 확대"로 조금씩 달라도 이름을 계속 바꾸지 않는다.
- Event는 **canonical_id + canonical_title(대표명)**로 고정.
- 새 기사는 그 ID에 편입만.
- **canonical_title에 감성 평가어 금지**: "실적 발표"(O) / "실적 호조"(X).
  이벤트는 사실만, 감성은 붙은 기사들의 분포가 표현한다.

## 7. 증분편입 (매시간)

전체 재군집화(모든 기사 다시 묶기)는 하지 않는다.
- 새 기사만 위 로직으로 기존 이벤트에 편입하거나 새로 생성.
- 기존 이벤트는 유지(ID·이름 안 바뀜).
- (선택) 하루 1회 전체 재정리로 누적 오차 리셋.

## 8. 구현 위치

- 계산 로직: services/event_merge.py
- 유사도 계산: utils/similarity.py
- 노드: nodes/merge_event.py (얇게, 위 서비스 호출)
- 테스트: tests/test_event_merge.py (핵심 로직이라 반드시)

## 9. 품질 평가 (evals)

병합은 tests(작동 확인)와 별개로 품질을 측정한다.
- 러너: evals/axes/event.py
- 정답셋: evals/datasets/event_goldset.jsonl (기사군 → 정답 클러스터/canonical, 사람 검수)
- 지표: 과병합/과분할을 보는 군집 지표(ARI, purity, 과병합률 등). RAGAS로는 커버 안 되는 프로젝트 고유 축.
