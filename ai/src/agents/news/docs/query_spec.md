# 질의 흐름 설계 (query_spec) — 자유 질문형 B

> 사용자 질문을 받아 지식그래프를 순회해 근거 있는 답변 + 리포트를 내는 흐름.
> 배치 흐름(수집·저장)은 그대로. 이 문서는 "질의 흐름"만 다룬다.
> 목표 출력(target UI): `veriθ News Report.html` 목업.

---

## 0. 확정 사항

- **B(자유 질문형)로 확정.** A(종목 선택형)는 B에 흡수(프리셋 질문).
- **출력 = HTML 리포트 하나.** ④ 답변(텍스트)은 **별도 채널이 아니라 리포트 안 `뉴스 흐름 요약` 섹션 + 근거 이슈 칩**으로 삽입한다(목업 구조 그대로). 텍스트만 따로 내보내지 않는다.
- **요약·답변 생성 모델 = Qwen3** (목업의 "Gemma" 표기는 Qwen3로 통일).
- **관련도 점수 = 미확정.** 잠정은 importance순 정렬로 대체(§6).

---

## 1. 전체 흐름

```
사용자 입력 (질문 문장  또는  종목 선택 = "이 종목 요약해줘")
   ↓
① 질문 이해 (LLM=Qwen3 → Pydantic)   회사 · 기간 · 의도 추출
   ↓
② 그래프 순회 (Neo4j)                single-hop / multi-hop 관계 조회
   ↓
③ 원문 요약 조회 (PostgreSQL)        이벤트에 붙은 기사 요약 + 감성
   ↓
④ 답변 생성 (LLM=Qwen3)              근거(news_id) 표시 + 데이터 없으면 "데이터 제한"
   ↓
출력:  HTML 리포트 하나
        └ ④ 답변이 "뉴스 흐름 요약" 섹션(+ 근거 이슈 칩)으로 내장 · 감성 게이지 · Top 이벤트
```

---

## 2. 단계별 상세

### ① 질문 이해
- 입력: 자유 문장 또는 종목.
- 출력(Pydantic): `companies[]`, `period`(기본 최근 7일), `intent`(관계 / 이유 / 요약 / 현황).
- 종목 선택은 `intent=요약, companies=[해당종목]` 프리셋으로 변환.
- **intent는 "뉴스 흐름 요약" 섹션의 초점·분량을 결정**(별도 텍스트 채널 on/off가 아님, 항상 HTML 안에 들어감):
  - 관계·이유 → 요약 섹션이 서사(왜/관계) 중심으로 길고 상세.
  - 요약·현황 → 요약 섹션이 짧고 분포·핵심 이슈 중심.
  - 근거가 부족하면 지어내지 말고 해당 섹션에 "데이터 제한" 표기(절대규칙 5).

### ② 그래프 순회 (Neo4j)
- **single-hop**: 한 회사가 참여한 이벤트. `(Company)-[:PARTICIPATES_IN]->(Event)`.
- **multi-hop**: 두 회사를 잇는 공유 이벤트. 예:
  `삼성전자 ─참여─▶ HBM 공급 계약 ◀─참여─ 엔비디아`.
  두 회사가 함께 `PARTICIPATES_IN`한 Event를 찾는다(관계 질문의 핵심).
- 기간 필터(최근 7일 등) 적용. 결과 = 관련 Event 집합.
- news는 그래프를 "탐색 요청"으로 설계, 실제 Neo4j 조회는 backend가 수행(HTTP).

### ③ 원문 요약 조회 (PostgreSQL)
- ②의 Event에 연결된 news_id → PostgreSQL에서 기사 요약·감성·출처·published_at 조회.
- 감성 count는 저장 안 함 → 이때 실시간 집계(이벤트별 긍/중/부 분포).

### ④ 답변 생성 (LLM=Qwen3)
- ③의 요약을 근거로 답변 작성.
- **이 답변 텍스트가 곧 HTML의 `뉴스 흐름 요약` 섹션 본문**이다. 언급한 핵심 이슈는 "근거 이슈 칩"(예: `#1 4분기 실적 발표`)으로 이벤트에 링크한다.
- **모든 주장에 근거 news_id 부착**(어떤 기사가 근거인지 추적 가능). 칩→이벤트→기사 순으로 추적된다.
- 관련 데이터 없으면 지어내지 말고 섹션에 "데이터 제한" 표기(절대규칙 5).
- report_renderer가 이 답변을 목업의 `뉴스 흐름 요약` 블록 자리에 렌더한다(별도 텍스트 출력 없음).

## 3. 목표 출력 (target UI) → 데이터 매핑

`veriθ News Report.html` 목업의 각 요소가 어느 단계 산출물인지:

| UI 요소 | 내용 | 출처 단계 |
|---|---|---|
| 헤더 (종목·집계기간·원문/중복제거 건수) | 삼성전자 · 최근 7일 · 318→142건 | ③ 메타 |
| 감성 게이지 (+0.41, 긍/중/부 %) | 전체 감성 분포 | ③ 실시간 집계 |
| 분석 기사 수 · 반응도 | 142건 · 평소比 1.8배 | ③ 집계 |
| **뉴스 흐름 요약 (근거 이슈 칩)** | **④ 답변 텍스트 그 자체**(Qwen3 생성) + 근거 이벤트 칩 | ④ + 근거 |
| 주요 이슈 TOP N | 관련도순 이벤트 목록 | ② + §6 정렬 |
| 이슈 상세 패널 (감성 분포 + 관련 기사) | 이벤트별 근·부·중 + 근거 기사 | ③ |
| "추정으로 채우지 않습니다" 배지 | 근거 검증 표시 | 절대규칙 5 |

- 관계 질문(두 회사)일 땐 같은 레이아웃을 쓰되 **초점이 "관계"로 이동**: 상단 요약 = 두 회사를 잇는 사건, TOP 이슈 = 공유 이벤트 위주.

## 4. 구현 위치

- `nodes/query.py` — 질문이해 → 그래프탐색 → 요약조회 순서(얇게).
- `services/query_understanding.py` — ① 질문 파싱(Qwen3). **신규 추가 예정.**
- `services/graph_query.py` — ② Neo4j 탐색 설계(single/multi-hop). **신규 추가 예정.**
- `services/backend/query_client.py` — ②③ backend HTTP 조회.
- `nodes/report.py` + `services/report_renderer.py` + `templates/report.html` — 답변+리포트 렌더.
- `schemas/query.py` — 질문 파싱 결과 + 답변 구조(answer 텍스트 + evidence news_id[]). **신규 추가 예정.**

> 위 "신규 추가 예정" 파일은 아직 미작성. 이 문서는 계획이며 코드는 별도 작업에서 만든다.

---

## 5. 품질 평가 연계 (evals answer 축)

자유 질문은 환각·근거 통제가 생명 → evals answer 축이 핵심.
- faithfulness(환각 여부), answer correctness/relevancy → evals/metrics/judge (RAGAS 어댑터).
- source_traceability(근거 news_id 추적) → evals/metrics/deterministic.
- 정답셋: evals/datasets/qa_goldset.jsonl (질의→정답+evidence_path).

---

## 6. 미확정: 관련도 점수 (추후 고민)

질의 결과(이벤트/기사)를 무슨 기준으로 랭킹할지 아직 안 정함. 후보:
- **(잠정) importance 재사용**: 기사수 + 언론사가중치 + 감성절대값. 지금은 이걸로 정렬.
- **질문-이벤트 적합도 별도 산출**: 질문 임베딩 ↔ 이벤트 summary 유사도(질문에 얼마나 맞는가)를 추가 반영.
- 결정 시 config.py로 빼고 실데이터 튜닝. HANDOFF 미확정 항목과 동기화.

---
