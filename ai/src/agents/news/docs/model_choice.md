# 모델 선택 근거 (model_choice)

> 3개 모델을 각자 역할에 맞게 분업. 왜 이 모델인지 근거.
> (+ 평가용 심판 모델 별도)

## 모델 스택 요약

| 역할 | 모델 | 서비스 |
|---|---|---|
| 추출 | Qwen3 30B-A3B (로컬) | llm.py |
| 감성 | KR-FinBert-SC | finbert.py |
| 임베딩 | arctic-embed-l-v2.0-ko | embedder.py |
| 평가(judge) | 파이프라인보다 같거나 강한 외부 챗모델 (교체 가능) | evals/metrics/judge/ |

**분업 원칙**: 각 모델이 잘하는 것만. LLM은 추출만, 감성은 전용 모델, 유사도는 임베딩 모델.
평가 심판은 파이프라인 모델과 분리한다(자기 채점 편향 방지).

---

## 1. 추출: Qwen3 30B-A3B (로컬)

- **역할**: 기사 본문 → 요약·기업·인물·산업·이벤트·키워드 추출.
- **왜 로컬**: 400건 매시간 처리 시 API 호출 비용·횟수 제한이 걸림돌.
  로컬이면 호출 비용 0, 횟수 무제한. 기사 본문이 외부로 안 나감(보안).
- **왜 이 모델**: MoE 구조(A3B=활성 3B). 30B급 품질을 3B급 속도로 처리 →
  대량 처리에 유리. 6비트 양자화(Q6)라 메모리 절약, 품질 손실 적음.
- **주의**: 속도(400건/시간)는 실측 필요. 배치 처리·짧은 출력·짧은 입력으로 최적화.

## 2. 감성: KR-FinBert-SC

- **역할**: 기사별 긍정/중립/부정 판정.
- **왜 이 모델**: 한국어 + 금융 도메인 특화(서울대 NLP랩, FinBERT 기반 한국어 경제 기사 학습).
  일반 한국어 감성 모델은 "어닝쇼크" 같은 금융 표현을 못 잡음.
- **왜 LLM 안 씀**: 전용 모델이 더 정확하고, LLM 부담도 줄임. 감성을 LLM에 맡기면 환각·부정확.

## 3. 임베딩: arctic-embed-l-v2.0-ko

- **역할**: summary 임베딩 → 이벤트 병합 유사도, 유사 검색.
- **왜 이 모델**: 한국어 검색 SOTA급(고려대 KURE 벤치마크 상위).
  처리량이 강점(대량 매시간 처리에 유리). 8K 컨텍스트로 긴 요약도 처리.
- **비교**: dragonkue/BGE-m3-ko가 정확도 근소 우위, arctic이 속도 우위.
  400건 매시간 요구 때문에 arctic 선택. (실데이터로 재확인 권장)
- **실험 결과**: 이전 ko-sroberta에서 이 모델로 교체 후 군집화 품질 크게 개선
  (예: "국민연금 매도폭탄설" 관련 기사들이 정확히 한 이벤트로 묶임).
- **주의**: arctic은 검색용 query/document 프리픽스 규칙이 있으나,
  기사끼리 유사도 비교(대칭)라 프리픽스 없이 모든 기사를 같은 방식으로 임베딩.

## 4. 왜 세 모델을 나누나 (한 모델로 안 하나)

- 한 LLM에 다 시키면: 감성 부정확 + 환각 + 느림 + 비쌈.
- 나누면: 각자 강점만 씀. 감성은 전용 모델이 정확, 임베딩은 전용 모델이 빠름,
  LLM은 추출(잘하는 것)만. 역할이 안 겹침.

## 5. RAG 평가 모델 (evals의 judge)

파이프라인 모델과 **별개**로, 품질 평가에만 쓰는 모델. 서비스가 아니라 `evals/`에서만 호출한다.

- **역할**: RAG 질의(answer 축)의 답변을 LLM-as-judge로 채점(faithfulness, answer correctness/relevancy 등).
- **어떤 지표에 쓰나**: LLM이 필요한 answer 축(릴리스 게이트)에만. 검색·구조·근거·온톨로지 등
  **결정적 지표는 모델이 필요 없다**(계산으로 채점, CI 상시, 비용 0). 감성·병합도 모델 없이 정답셋 대조.
- **어떤 모델을 쓰나**: 피평가(로컬 Qwen3)와 **같거나 더 강한 외부 챗모델**을 권장.
  피평가 모델을 심판으로 쓰면 자기 답을 후하게 보는 **자기 채점 편향**이 생긴다.
- **교체 가능(핵심)**: `evals/metrics/judge/ragas_adapter.py`(RAGAS 격리 래퍼) 하나에만 심판 모델을 꽂는다.
  RAGAS 호환이 깨지면 `fallback_judge.py`(함수형 경량 구현)로 한 줄 교체. 나머지 코드는 심판을 직접 import 안 함.
- **주의**:
  - 심판 점수는 절대 품질이 아니라 그 심판·프롬프트 아래의 **상대 지표**. 변경 전후 비교용으로 쓴다.
  - 중요한 평가는 더 강한 모델로 교차검증하고 표본을 사람이 검수한다.
  - 한국어 뉴스 도메인이므로 심판 모델의 한국어 능력을 확인한다.
  - 호출 비용·비결정성 때문에 매 커밋이 아니라 릴리스 게이트에서만 돌린다.
